# Evidence and confidence

Code shows what a system does. Pull requests and issues can show why an author made a change. They do not always give a complete answer.

Give each conclusion one confidence level.

## Direct

The author states the reason in a pull-request description, comment, review, or linked issue. State the claim directly. Cite the source.

## Supported

Several independent sources support the same reason. State the claim with the evidence. Cite each source.

## Inferred

The record supports a likely meaning, but no source states it. Use cautious language. Show the evidence and the inference.

## Speculative

The record permits an explanation but gives little support. Label it as speculation. State an unknown instead when speculation has little value.

## Unknown

The pull request and linked issue do not answer the question. State what you read and what is still unknown.

## Rules

- Do not use code as evidence of its own intent.
- Do not treat a user hypothesis as a conclusion.
- Keep contradictions between sources.
- Do not state an inference as a fact.
- Cite every Direct or Supported claim.
