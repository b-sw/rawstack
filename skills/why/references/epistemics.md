# Evidence and confidence

Code shows what a system does. Pull-request text and issue text can show why an author made a change. Neither source always gives a complete answer.

Classify every conclusion in one of these tiers.

## Direct

The author explicitly states the reason in a pull-request description, comment, review, or linked issue. State the claim directly and cite the source.

## Supported

Several independent items point to the same reason. State the claim with the evidence and cite every item.

## Inferred

The record supports a likely interpretation but no source states it directly. Use hedged language. Show the evidence and the inference.

## Speculative

The record permits an explanation but does not support it well. Label it as speculation. Prefer an explicit gap when speculation has little value.

## Unknown

The pull request and linked issue do not answer the question. State what you read and what remains unknown.

## Rules

- Do not cite code as evidence of its own intent.
- Do not treat a user hypothesis as a conclusion.
- Preserve contradictions between sources.
- Do not promote an inference to a fact.
- Cite every direct or supported claim.
